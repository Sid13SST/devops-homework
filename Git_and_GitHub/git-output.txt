==================================================
== TASK 1 - git commit -m   VS   git commit -a -m
==================================================

### Step 1: create a file and make the FIRST commit.
### A brand new file is UNTRACKED, so it must be staged with 'git add' first.
$ echo 'version 1' > app.txt

$ git status --short
?? app.txt

--- '??' means untracked. Try committing with -a -m and watch it be ignored:
$ git commit -a -m 'attempt to commit an untracked file'
On branch main

Initial commit

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	app.txt

nothing added to commit but untracked files present (use "git add" to track)

>>> RESULT: nothing was committed. -a does NOT pick up UNTRACKED files.

$ git add app.txt

$ git commit -m 'commit 1: add app.txt'
[main (root-commit) 2f5f576] commit 1: add app.txt
 1 file changed, 1 insertion(+)
 create mode 100644 app.txt

### Step 2: MODIFY the now-tracked file.
$ echo 'version 2' > app.txt

$ git status --short
 M app.txt

--- ' M' means a TRACKED file was modified but not staged.

### Step 3: 'git commit -m' alone commits NOTHING here, because nothing is staged.
$ git commit -m 'commit with -m only'
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   app.txt

no changes added to commit (use "git add" and/or "git commit -a")

>>> RESULT: refused - 'no changes added to commit'.

### Step 4: 'git commit -a -m' stages all MODIFIED TRACKED files automatically.
$ git commit -a -m 'commit 2: update app.txt using -a -m'
[main c4fd096] commit 2: update app.txt using -a -m
 1 file changed, 1 insertion(+), 1 deletion(-)

>>> RESULT: committed in one step - no separate 'git add' needed.
$ git log --oneline
c4fd096 commit 2: update app.txt using -a -m
2f5f576 commit 1: add app.txt

### Step 5: side-by-side proof with BOTH a modified tracked file and a new untracked file.
$ echo 'version 3' > app.txt

$ echo 'brand new file' > newfile.txt

$ git status --short
 M app.txt
?? newfile.txt

$ git commit -a -m 'commit 3: -a picks up app.txt but not newfile.txt'
[main 54b22c1] commit 3: -a picks up app.txt but not newfile.txt
 1 file changed, 1 insertion(+), 1 deletion(-)

$ git status --short
?? newfile.txt

>>> app.txt was committed. newfile.txt is STILL untracked ('??').

$ git add newfile.txt && git commit -m 'commit 4: add newfile.txt explicitly'
[main 377c54d] commit 4: add newfile.txt explicitly
 1 file changed, 1 insertion(+)
 create mode 100644 newfile.txt

$ git status --short

$ git log --oneline
377c54d commit 4: add newfile.txt explicitly
54b22c1 commit 3: -a picks up app.txt but not newfile.txt
c4fd096 commit 2: update app.txt using -a -m
2f5f576 commit 1: add app.txt


SUMMARY OF TASK 1
-----------------
  git commit -m 'msg'      -> commits ONLY what is already staged (git add).
  git commit -a -m 'msg'   -> automatically stages every MODIFIED and DELETED
                              TRACKED file, then commits. It still IGNORES
                              untracked (brand new) files.
